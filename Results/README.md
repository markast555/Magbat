# Результаты экспериментов

Сравнение событийной и циклической обработки команд в серверной части пошаговой игры.
Каждая серия лежит в своём файле `results_<дата>_<время>.csv`. Формат: разделитель `;`,
десятичная запятая, кодировка UTF-8 с BOM (Excel открывает двойным щелчком).
Чтение в pandas: `pd.read_csv(path, sep=";", decimal=",", encoding="utf-8-sig")`.

## Окружение

- Процессор: AMD Ryzen 7 5700X
- Память: 16 ГБ, ADATA XPG GAMMIX D20 (AX4U320016G16A-CBK20)
- ОС: Windows 11
- Платформа: .NET 8.0.33 (среда выполнения), SDK 9.0.312
- Запуск: Release, `dotnet run -c Release` в терминале, без профилировщика Rider
- Фоновые программы: закрыты все, кроме Rider
- Условия считаются одинаковыми для всех серий в этой папке. Если они изменятся, добавить отдельный раздел

## Столбцы (основные)

- `server`: модель (event, tickЧАСТОТА_delta или tickЧАСТОТА_snapshot)
- `games`, `think_ms`, `delay_ms`, `repeat`: параметры прогона
- `lat_mean_ms`, `lat_p95_ms`: отклик на собственные команды клиента
- `server_busy_pct`: время активной работы потока сервера, % одного ядра (без ожидания)
- `server_cpu_pct`: процессорное время потока по данным Windows (учёт грубый, ступенями около 0,035%)
- `traffic_bytes_per_s`, `bytes_per_cmd`: трафик по доставленным сообщениям (обе копии игрокам)
- `busy_ms_per_cmd`: нагрузка сервера на одну команду
- `ticks`, `idle_ticks`, `tick_*_ms`: тики и фактические интервалы (только циклический сервер)


## Ограничения

- Сеть эмулируется внутри процесса, потерь пакетов и джиттера нет
- Клиенты и сервер работают на одной машине и делят процессор
- Шаг системного таймера Windows не менялся (около 15,6 мс)
- При 1 партии и паузе 3000 мс команд в окне 4-5, отклик и p95 не показательны
- Преимущество снимков в надёжности (потерянные пакеты) не оценивается
